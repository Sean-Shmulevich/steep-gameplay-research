ANIMATION GRAPH AND POSE BLENDING

Run python3 reference.py. The reference uses Python's standard library and synthetic named inputs. Examples are mathematical illustrations, not extracted rider animation clips.

Documented graph evaluation
SimpleBlendNode obtains its child weights from graph inputs, clamps negatives to zero, chooses the first strict maximum as the dominant child, and normalizes by their sum. If the sum is below 0.00001, the helper replaces the first weight with one and leaves the other weights unchanged. This matters for tiny nonzero values: it does not clear the whole array. An empty array stays empty. The pose evaluator visits children in stored order and skips weights at or below 0.00001. The first active child supplies the pose. For each following active child, running_sum += weight and alpha=weight/running_sum, then the child is blended into the current pose. Child evaluation receives parent_weight*child_weight. The dominant child's context is retained separately. Translation blending is equivalent to a normalized weighted average when all children use linear translation; normalized quaternion combinations can depend on child order.

AxialBlendNode reads the coordinate and ordered knot values, clamps the coordinate to the first/last knot, and finds the first right knot strictly greater than the coordinate. It computes alpha=clamp((coordinate-left)/(right-left),0,1). An alpha within 0.00001 of zero selects the left child directly; reaching the final endpoint selects the final child. The returned pair otherwise refers to neighboring knots. Single-knot nodes select their only child. The reference expects ordered finite knots. It does not invent behavior for malformed graph assets.

Regular channel equations
Float scalar and four-component translation/vector channels use output=A+weight*(B-A). Integer and byte channels use an integer weight trunc(weight*255) and integer division by255. The complete integer signedness and overflow rules are not ported. Channel descriptors choose the typed operation; they are not all assumed to be bone rotations. Runtime skeleton local transforms use translation followed by an XYZW quaternion, consistent with the skeleton chapter.

Bone quaternion blend has three regimes. Let d=dot(A,B) for normalized XYZW inputs. If abs(abs(d)-1)<=2^-23, it copies A regardless of weight. Otherwise, if d is below 0.98935598135, it aligns B to A's hemisphere when d<0, applies the polynomial blend below, and normalizes. For the remaining close positive-dot case, it normalizes A+weight*(B-A). This is not exact trigonometric slerp. Normalization in the machine uses reciprocal-square-root estimate followed by a Newton correction; the portable version uses host square root, with measured errors below one millionth in the tested cases.

Polynomial quaternion equation
For the polynomial helper's input pair, let d=dot(A,B), k=0.58549219370*(1-0.82279688120*d)^2. Define L(u)=u*(1+k+(2*u-3)*k*u). Corrected weight c=L(weight) when weight<=0.5; otherwise c=1-L(1-weight). Flip B if this helper's d<0, then normalize A+c*(B-A). The regular bone caller performs hemisphere alignment before this polynomial, so its k sees a nonnegative dot. The standalone additive helper derives k from its delta quaternion's signed dot with identity before its sign correction. reference.py preserves that distinction. Inputs and polynomial arithmetic are rounded to float32. No universal weight clamp was documented in these local helpers.

Additive layers
For a weighted translation delta, output=base+weight*delta. For a weighted rotation delta, first polynomial-blend identity quaternion toward the delta, then output=base_quaternion*weighted_delta_quaternion using Hamilton multiplication in XYZW order. This multiplication order is validated with rotations about different axes. Full-weight fast paths add translation directly and multiply rotations directly. The scalar channel in the weighted additive typed helper uses scalar lerp rather than base+weight*delta; do not apply the vector equation to every channel type. Named PoseBlend_Additive configuration reaches the engine's additive dispatch through the registered BlendSkeletonPose callback. RotationInGlobal has a distinct transform path; its full correction/basis handling is not ported here.

Selection and channel masks
The engine can select stored channel groups using mask bits. In a supported channel group carrying a byte weight, effective_weight=global_weight*mask_byte/255. The selected source for that byte depends on the caller's mode. A companion group mask can force the constant global weight for selected groups instead. A typed exclusion mask skips channel operations by channel kind. The reference exposes the effective byte equation; exact named rider bone masks and their graph producers were not decoded, so no fabricated upper/lower-body mask is supplied.

Graph displacement uses a different rotation helper
The graph's displacement-pose rotation blends first compute normalized linear blending, then replace it with true-trigonometric slerp when dot is below 0.98935574293. The true-trigonometric helper copies target B when dot<=-1, dot>=1, or acos(abs(dot))<=0.000001, regardless of weight. Otherwise theta=acos(abs(dot)); output=normalize(A*sin((1-weight)*theta)/sin(theta) + sign(dot)*B*sin(weight*theta)/sin(theta)). Translation uses linear interpolation for the named Linear algorithm. Circular and Elliptical modes share a direction/radius interpolation path with a linear fallback; the full robust implementation is not included. The documented bone helper, graph displacement helper and IK helper must remain separate because their endpoint and approximation rules differ.

Clip phase and time intervals
AnimationDataNode supplies normalized start phase and phase delta to the displacement sampler. With animation length T, sampled_start=T*start_phase and sampled_end=sampled_start+T*phase_delta. The length comes through the named GetAnimationResourceLength callback. A phase difference helper computes delta=end-start, records crossed=(delta<0), then repeatedly adds one while delta<0. It does not reduce positive differences greater than one. The reference also implements the phase remapping wrapper: values inside [0,1], including exactly one, survive; values outside wrap with fmod and negative values add the upper endpoint. A collapsed range returns the lower endpoint. This inclusive endpoint behavior differs from ordinary modulo. Graph remapping can use synchronized marker tables before wrapping; marker-table mapping remains outside this reference.

Boundaries
These are runnable blocks with actual graph-to-engine connections. They do not reproduce the full rider animation state machine. Per-frame elapsed-time to phase generation, playback rate producers, concrete transition conditions and duration/weight policies, compressed animation sampling, named rider clips and bone-mask assets remain unresolved. The package records documented type and enum names, not invented game configurations. The skeleton package supplies documented skeleton hierarchies and bind transforms separately.
